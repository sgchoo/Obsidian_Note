# 데이터베이스 관계 해소 방법

## 1:1 관계 해소

### 1. 하나의 엔티티 타입으로 통합

**적용 조건**:

- 동일한 PK 구조를 가지는 1:1 관계
- PK가 동일하게 사용되는 경우
- 한 시점에 두 엔티티 타입이 동시 발생하지 않는 경우
- 두 엔티티 타입의 속성들이 비슷한 경우

**결과**: 완전히 하나의 엔티티 타입으로 통합

### 2. 부분 통합

**적용 조건**:

- PK는 동일하지만 내용이 다른 경우
- PK 속성들의 구조가 모두 비슷한 경우

**해소 방법**:

- 별도 엔티티 타입으로 유지
- 또는 하나의 엔티티 타입으로 통합 시 PK를 변경하여 통합
- 편의상 하나로 통합하여 표현

### 3. 슈퍼 엔티티 타입 생성

**적용 조건**:

- PK와 의미가 동일한 경우
- 속성의 일부만 다른 경우
- 엔티티 타입의 PK가 같고, 동일한 속성을 가지고 있는 경우
- 일부 속성이 다르거나 각각의 관계가 다른 엔티티 타입과 상이한 경우

**결과**: 공통 속성을 가진 슈퍼타입으로 통합

## M:N 관계 해소

### Bridge Table 생성

**해소 방법**:

- 각 테이블의 PK를 FK로 참조
- 연결 테이블(Bridge Table)을 사용하여 해소

**구조**:

```
테이블 A (PK: A_ID) ──┐
                     ├── Bridge Table (FK: A_ID, B_ID)
테이블 B (PK: B_ID) ──┘
```

**특징**:

- M:N 관계를 1:M과 M:1 관계로 분해
- Bridge Table은 양쪽 테이블의 PK를 FK로 가짐
- 필요에 따라 추가 속성을 Bridge Table에 포함 가능
