# 데이터베이스 기본 개념

## 데이터와 정보

### 데이터 (Data)

- 현실에서 관찰하거나 습득한 사실이나 값
- 가공되지 않은 원시 자료

### 정보 (Information)

- 데이터를 어떤 방법으로 처리해서 의미를 가지는 단위로 처리한 것

### 정보처리 (Information Processing)

- 데이터에서 정보를 추출하는 과정 또는 방법

## 데이터의 분류

### 정량적 데이터 (정형 데이터)

- 도형, 수치, 기호 등으로 수치화할 수 있는 데이터
- 구조화되어 있어 분석이 용이함

### 정성적 데이터 (비정형 데이터)

- 언어, 소리, 문자 등의 비정형 데이터
- 구조화되지 않아 처리가 복잡함

## 정보 시스템과 데이터베이스

### 정보 시스템 (Information System)

- 조직 운영에 필요한 데이터를 수집하여 저장해두었다가, 필요할 때 정보로 가공하는 시스템

### 데이터베이스 시스템 (Database System)

- 정보 시스템 안에서 데이터를 저장하고 있다가 필요할 때, 데이터를 전달하는 역할

## 데이터베이스의 정의

- 논리적으로 연관된 데이터를 모아 일정한 형태로 저장해 놓은 것
- 중복 데이터를 최소화하여 조직의 목적에 맞게 관리하는 것

### ISOS - 데이터베이스의 4가지 특성

1. **통합된 데이터 (Integrated Data)**
    
    - 데이터 중복을 최소화한 데이터
2. **저장된 데이터 (Stored Data)**
    
    - 컴퓨터가 접근할 수 있는 저장 매체에 저장된 데이터
3. **운영 데이터 (Operational Data)**
    
    - 조직의 고유한 업무를 수행하는데 반드시 필요한 데이터
4. **공용 데이터 (Shared Data)**
    
    - 여러 응용 시스템이 공동으로 소유하고 유지하는 데이터

## 데이터베이스 시스템의 특징

### R1C3 - 데이터베이스 시스템의 4가지 특징

1. **실시간 접근성 (Real Time Accessibility)**
    
    - 사용자의 요구에 대해 실시간으로 응답
2. **지속적인 변화 (Continuous Evolution)**
    
    - 새로운 데이터의 삽입, 삭제, 갱신을 통해 항상 최신 정보 유지
3. **동시 공유 (Concurrent Sharing)**
    
    - 여러 사용자가 동시에 같은 데이터를 공유하여 사용
4. **내용에 의한 참조 (Content Reference)**
    
    - 사용자가 요구하는 데이터 내용으로 해당 데이터 참조

## 릴레이션 (Relation)

### 릴레이션의 개념

- 행과 열로 구성된 테이블
- 릴레이션십은 테이블과의 관계를 뜻함
- 릴레이션은 수학의 집합에서 나온 개념

## 릴레이션 스키마 (Relation Schema)

### 스키마의 정의

- 관계 데이터베이스의 릴레이션 구성과 어떤 정보를 담고 있는지에 대한 기본 구조를 정의

### 스키마의 구성 요소

- **헤더**: 첫 행으로, 각 데이터의 특징을 나타내는 속성, 데이터 타입 등의 정보를 포함
- **속성 (Attribute)**: 각 열을 의미하며, 각각 고유한 이름을 가짐
- **도메인 (Domain)**: 속성의 값이 무엇인지 정의
- **차수 (Degree)**: 릴레이션이 가지는 속성의 개수

## 릴레이션 인스턴스 (Relation Instance)

### 인스턴스의 개념

- 릴레이션 스키마에 저장된 데이터의 집합

### 인스턴스의 구성 요소

- **튜플 (Tuple)**: 릴레이션에서 한 행
- **카디널리티 (Cardinality)**: 릴레이션에 저장된 튜플의 수

## 릴레이션의 특징

1. **속성은 단일 값으로 구성**
2. **속성은 서로 다른 이름으로 구성**
3. **한 속성의 값은 모두 같은 도메인으로 구성**
4. **속성의 순서는 상관없음**
5. **릴레이션 내의 중복된 튜플은 허용하지 않음**
6. **튜플의 순서는 상관없음**

## 릴레이션 키의 종류

### 1. 슈퍼키 (Super Key)

- 튜플을 유일하게 식별할 수 있는 하나의 속성 또는 속성 집합
- 튜플을 유일하게 식별할 수 있는 값이면 모두 슈퍼키 가능
- 슈퍼키는 포함하지 않아도 되는 속성을 포함할 수 있음
- 튜플을 식별할 수 있는 최소한의 속성 집합
- 키를 구성하는 속성이 많으면 관계 표현이 복잡해짐

### 2. 후보키 (Candidate Key)

- 튜플을 유일하게 식별할 수 있는 속성의 최소 집합
- 효율성 측면에서 매우 중요
- 슈퍼키에서 없어도 되는 속성을 포함하면 후보키가 아님

### 3. 대리키 (Surrogate Key)

- 기본키가 보안을 요하거나, 여러 개의 속성으로 구성되어 복잡하거나 마땅한 기본키가 없을 때 일련번호 같은 가상의 속성을 만들어 기본 키로 사용
- 소프트웨어에서 임의로 생성하는 값으로 사용자가 직관적으로 그 값의 의미를 알 수 없음

### 4. 대체키 (Alternate Key)

- 기본키로 선정되지 않은 후보키
