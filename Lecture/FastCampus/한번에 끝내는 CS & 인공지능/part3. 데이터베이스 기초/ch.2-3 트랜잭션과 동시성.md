# 데이터베이스 트랜잭션 (Database Transaction)

## 트랜잭션이란?

트랜잭션(Transaction)은 데이터베이스에서 하나의 논리적 작업 단위를 의미합니다. 여러 개의 데이터베이스 연산들을 하나의 그룹으로 묶어서, 모든 연산이 성공적으로 완료되거나 모두 취소되도록 보장하는 메커니즘입니다.

## ACID 속성

트랜잭션은 다음 네 가지 중요한 속성을 만족해야 합니다:

### 원자성 (Atomicity)

- 트랜잭션의 모든 연산이 완전히 수행되거나 전혀 수행되지 않아야 함
- "All or Nothing" 원칙
- 중간에 실패하면 이전 상태로 완전히 롤백

### 일관성 (Consistency)

- 트랜잭션 실행 전후에 데이터베이스가 일관된 상태를 유지해야 함
- 모든 데이터 무결성 제약조건을 만족해야 함
- 비즈니스 규칙과 제약사항이 위반되지 않아야 함

### 격리성 (Isolation)

- 동시에 실행되는 트랜잭션들이 서로 영향을 주지 않아야 함
- 각 트랜잭션은 독립적으로 실행되는 것처럼 보여야 함
- 중간 결과가 다른 트랜잭션에 노출되지 않아야 함

### 지속성 (Durability)

- 성공적으로 완료된 트랜잭션의 결과는 영구적으로 저장되어야 함
- 시스템 장애가 발생해도 커밋된 데이터는 손실되지 않아야 함

## 트랜잭션 상태

트랜잭션은 다음과 같은 상태를 가집니다:

1. **활성 (Active)**: 트랜잭션이 실행 중인 상태
2. **부분 완료 (Partially Committed)**: 마지막 명령문이 실행된 상태
3. **완료 (Committed)**: 트랜잭션이 성공적으로 완료된 상태
4. **실패 (Failed)**: 정상적인 실행이 불가능한 상태
5. **중단 (Aborted)**: 트랜잭션이 롤백되고 이전 상태로 복구된 상태

## 트랜잭션 제어 명령어

### BEGIN/START TRANSACTION

```sql
BEGIN;
-- 또는
START TRANSACTION;
```

트랜잭션의 시작을 명시적으로 선언합니다.

### COMMIT

```sql
COMMIT;
```

트랜잭션의 모든 변경사항을 데이터베이스에 영구적으로 반영합니다.

### ROLLBACK

```sql
ROLLBACK;
```

트랜잭션의 모든 변경사항을 취소하고 이전 상태로 되돌립니다.

### SAVEPOINT

```sql
SAVEPOINT savepoint_name;
ROLLBACK TO savepoint_name;
```

트랜잭션 내에서 중간 지점을 설정하여 부분 롤백을 가능하게 합니다.

## 격리 수준 (Isolation Levels)

동시성 제어를 위해 다음과 같은 격리 수준을 제공합니다:

### READ UNCOMMITTED

- 가장 낮은 격리 수준
- 다른 트랜잭션의 커밋되지 않은 데이터도 읽을 수 있음
- Dirty Read 발생 가능

### READ COMMITTED

- 커밋된 데이터만 읽을 수 있음
- Dirty Read 방지
- Non-repeatable Read 발생 가능

### REPEATABLE READ

- 같은 데이터를 여러 번 읽어도 동일한 결과 보장
- Non-repeatable Read 방지
- Phantom Read 발생 가능

### SERIALIZABLE

- 가장 높은 격리 수준
- 트랜잭션들이 순차적으로 실행되는 것과 동일한 결과
- 모든 이상 현상 방지

## 동시성 문제

### Dirty Read

- 커밋되지 않은 데이터를 읽는 현상
- 나중에 롤백될 수 있는 데이터를 기반으로 작업 수행

### Non-repeatable Read

- 같은 트랜잭션 내에서 같은 데이터를 두 번 읽었을 때 결과가 다른 현상
- 중간에 다른 트랜잭션이 데이터를 수정한 경우 발생

### Phantom Read

- 같은 조건으로 두 번 검색했을 때 결과 행의 수가 달라지는 현상
- 중간에 다른 트랜잭션이 행을 삽입하거나 삭제한 경우 발생

## 실제 예제

### 계좌 이체 트랜잭션

```sql
BEGIN;

-- A 계좌에서 100,000원 차감
UPDATE accounts 
SET balance = balance - 100000 
WHERE account_id = 'A';

-- B 계좌에 100,000원 입금
UPDATE accounts 
SET balance = balance + 100000 
WHERE account_id = 'B';

-- 모든 작업이 성공하면 커밋
COMMIT;

-- 문제가 발생하면 롤백
-- ROLLBACK;
```

### 재고 관리 트랜잭션

```sql
BEGIN;

-- 주문 정보 삽입
INSERT INTO orders (customer_id, product_id, quantity) 
VALUES (123, 456, 5);

-- 재고 차감
UPDATE inventory 
SET stock_quantity = stock_quantity - 5 
WHERE product_id = 456;

-- 재고가 음수가 되지 않는지 확인
SELECT stock_quantity FROM inventory WHERE product_id = 456;

-- 조건 만족 시 커밋
COMMIT;
```

## 트랜잭션 설계 원칙

### 짧은 트랜잭션 유지

- 트랜잭션은 가능한 한 짧게 유지하여 락 경합을 최소화
- 사용자 입력 대기나 네트워크 호출을 트랜잭션 내에 포함하지 않음

### 적절한 격리 수준 선택

- 비즈니스 요구사항에 맞는 최소한의 격리 수준 사용
- 성능과 일관성 사이의 균형 고려

### 데드락 방지

- 항상 동일한 순서로 리소스 접근
- 트랜잭션 시간 최소화
- 적절한 인덱스 설계

### 예외 처리

- 트랜잭션 실패 시 적절한 롤백 수행
- 재시도 로직 구현
- 로깅 및 모니터링

## 성능 최적화

### 인덱스 활용

- 트랜잭션에서 사용하는 쿼리에 적절한 인덱스 생성
- WHERE 절과 JOIN 조건에 사용되는 컬럼에 인덱스 적용

### 배치 처리

- 대량의 데이터 처리 시 배치 단위로 트랜잭션 분할
- 메모리 사용량과 락 시간 최소화

### 연결 풀 관리

- 데이터베이스 연결 풀을 효율적으로 관리
- 트랜잭션 완료 후 즉시 연결 반환

## 모니터링 및 디버깅

### 트랜잭션 로그 분석

- 트랜잭션 실행 시간 모니터링
- 롤백 빈도 추적
- 데드락 발생 패턴 분석

### 성능 메트릭

- 트랜잭션 처리량 (TPS)
- 평균 응답 시간
- 락 대기 시간
- 롤백률

트랜잭션은 데이터베이스의 핵심 개념으로, 데이터 무결성과 일관성을 보장하는 중요한 메커니즘입니다. 적절한 트랜잭션 설계와 관리를 통해 안정적이고 효율적인 데이터베이스 시스템을 구축할 수 있습니다.
