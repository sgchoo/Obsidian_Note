## 🌳 허프만 코딩(Huffman Coding)의 과정

### Step 1. 빈도수 구하기

- DATA: **AAAAFAAAAABBBBBAAAAACAAAAAAACBBBBBBCCBBBBDDDBBBBCCCAAAAAACCCCDDDDDEEEF**

제공된 데이터의 문자별 빈도수는 다음과 같습니다. (총 56개 문자)

- **A**: 20
    
- **B**: 15
    
- **C**: 10
    
- **D**: 6
    
- **E**: 3
    
- **F**: 2
    

---

### Step 2. 노드 준비 (개념 수정)

'내림차순 정렬' 대신, **'빈도수가 가장 낮은 노드'**를 항상 먼저 선택할 수 있도록 준비합니다.

이는 알고리즘에서 **'최소 우선순위 큐(Min-Priority Queue)'**를 사용하는 것과 같습니다. 수동으로 계산할 때는 단순히 빈도수가 가장 낮은 두 개를 계속 찾는다고 생각하면 됩니다.

- **시작 상태 (리프 노드 6개):** `(F:2)`, `(E:3)`, `(D:6)`, `(C:10)`, `(B:15)`, `(A:20)`
    

---

### Step 3. Tree 생성 (작은 빈도의 노드 합치기)

빈도수가 가장 낮은 두 노드를 선택하여 하나의 **'부모 노드'**로 합치는 과정을 반복합니다. 부모 노드의 빈도수는 두 자식 노드 빈도수의 합입니다.

1. **[F:2]**와 **[E:3]**을 합칩니다. (가장 작은 두 값)
    
    - 새 노드 **[N1: 5]** 생성
        
    - _현재 노드 목록:_ `(N1:5)`, `(D:6)`, `(C:10)`, `(B:15)`, `(A:20)`
        
2. **[N1: 5]**와 **[D:6]**을 합칩니다.
    
    - 새 노드 **[N2: 11]** 생성
        
    - _현재 노드 목록:_ `(C:10)`, `(N2:11)`, `(B:15)`, `(A:20)`
        
3. **[C:10]**과 **[N2: 11]**을 합칩니다.
    
    - 새 노드 **[N3: 21]** 생성
        
    - _현재 노드 목록:_ `(B:15)`, `(A:20)`, `(N3:21)`
        
4. **[B:15]**와 **[A:20]**을 합칩니다. (남은 노드 중 가장 작은 두 값)
    
    - 새 노드 **[N4: 35]** 생성
        
    - _현재 노드 목록:_ `(N3:21)`, `(N4:35)`
        
5. 마지막 남은 **[N3: 21]**과 **[N4: 35]**를 합칩니다.
    
    - 최종 **[Root: 56]** 노드 생성. 트리가 완성됩니다.
        

#### 🌲 완성된 허프만 트리

```
      (Root: 56)
     /          \
  (N3: 21)       (N4: 35)
  /      \         /      \
(C: 10) (N2: 11) (B: 15)  (A: 20)
        /      \
     (N1: 5)   (D: 6)
     /     \
   (F: 2)  (E: 3)
```

---

### Step 4. 코드 할당하기

완성된 트리에서 **왼쪽 가지(Branch)는 `0`**, **오른쪽 가지는 `1`**을 부여하여 루트에서부터 각 리프 노드(문자)까지의 경로를 코드로 만듭니다.

- **A**: 1 $\to$ 1 $\implies$ **`11`**
    
- **B**: 1 $\to$ 0 $\implies$ **`10`**
    
- **C**: 0 $\to$ 0 $\implies$ **`00`**
    
- **D**: 0 $\to$ 1 $\to$ 1 $\implies$ **`011`**
    
- **E**: 0 $\to$ 1 $\to$ 0 $\to$ 1 $\implies$ **`0101`**
    
- **F**: 0 $\to$ 1 $\to$ 0 $\to$ 0 $\implies$ **`0100`**
    

---

### Step 5. 압축 효율 계산 (보충)

|**문자**|**빈도수 (Freq)**|**할당 코드**|**코드 비트 수**|**총 비트 (Freq * Bits)**|
|---|---|---|---|---|
|A|20|`11`|2|40|
|B|15|`10`|2|30|
|C|10|`00`|2|20|
|D|6|`011`|3|18|
|E|3|`0101`|4|12|
|F|2|`0100`|4|8|
|**합계**|**56**|||**128 bits**|

**결과 비교:**

- **3-bit 고정 길이 인코딩:**
    
    - 6개의 문자를 구별하려면 최소 3 bit ($2^3=8$)가 필요합니다.
        
    - 56개 문자 $\times$ 3 bits = **168 bits**
        
- **허프만 코딩 (가변 길이):**
    
    - **128 bits**
        

**결론:** Tree 구조를 활용한 허프만 코딩을 통해, 빈도수가 높은 문자(A, B, C)에는 짧은 코드를, 빈도수가 낮은 문자(E, F)에는 긴 코드를 할당하여, 고정 길이 방식(168 bits)보다 더 효율적으로 데이터를 압축(128 bits)할 수 있습니다.
