# 패킷의 생성과 전달, 소멸

## 1. 데이터 전달의 기본 흐름

네트워크에서 데이터는 **프로세스(Process) → 네트워크 → 프로세스** 형태로 전달된다.

즉,

1. 어떤 **Process**가 다른 **Process**에게 데이터를 보내려고 한다.
2. OS의 네트워크 스택(TCP/IP Stack)이 데이터를 **Packet 형태로 캡슐화(Encapsulation)** 한다.
3. 패킷은 **Gateway(라우터)** 로 전달된다.
4. Gateway는 **Destination IP**를 확인하고 라우팅한다.
5. 목적지 **Host**에 도착한다.
6. Host는 **Port 번호**를 확인하여 해당 **Process**에게 데이터를 전달한다.

### 전체 흐름

Process → Socket → TCP/IP Stack → Packet → Network → Host → Process


---

# 2. 패킷 생성 과정 (Encapsulation)

데이터는 네트워크를 통해 전달될 때 **계층을 내려가면서 Header가 추가된다.**

```

Application Data  
↓  
Transport Layer (TCP)  
↓  
Network Layer (IP)  
↓  
Data Link Layer (MAC)

```

각 계층에서 **Header가 붙으면서 데이터 단위가 바뀐다.**

| 계층 | 데이터 단위 |
|-----|-------------|
| Transport Layer | Segment |
| Network Layer | Packet |
| Data Link Layer | Frame |

---

# 3. Encapsulation 구조

## 3.1 Segment (Transport Layer)

TCP 계층에서 생성되는 데이터 단위

```

[ Segment ]  
┌──────────────┬──────────────┐  
│ TCP Header │ Payload │  
└──────────────┴──────────────┘

```

### TCP Header 역할

- Source Port
- Destination Port
- Sequence Number
- ACK Number
- Control Flags (SYN, ACK 등)

즉 **어떤 프로세스와 통신할지 결정한다.**

---

## 3.2 Packet (Network Layer)

Segment 앞에 **IP Header**가 추가된다.

```

[ Packet ]  
┌──────────────┬────────────────────────┐  
│ IP Header │ TCP Header + Payload │  
└──────────────┴────────────────────────┘

```

### IP Header 역할

- Source IP
- Destination IP
- TTL
- Protocol (TCP / UDP)

즉 **어떤 Host로 보낼지 결정한다.**

---

## 3.3 Frame (Data Link Layer)

Packet 앞에 **MAC Header**가 추가된다.

```

[ Frame ]  
┌──────────────┬────────────────────────────────────┐  
│ MAC Header │ IP Header + TCP Header + Data │  
└──────────────┴────────────────────────────────────┘

```

### MAC Header 역할

- Source MAC Address
- Destination MAC Address
- EtherType

즉 **같은 네트워크에서 어떤 장치에게 전달할지 결정한다.**

---

# 4. 데이터 전달 과정

실제 네트워크에서는 다음 흐름으로 데이터가 이동한다.

```

Application Data  
↓  
Segment 생성  
↓  
Packet 생성  
↓  
Frame 생성  
↓  
Network 전송  
↓  
Destination Host 도착  
↓  
Frame 제거  
↓  
Packet 제거  
↓  
Segment 확인  
↓  
Process 전달

```

목적지에서 Header를 하나씩 제거하는 과정을 **Decapsulation**이라고 한다.

---

# 5. Socket

Socket은 **TCP/IP 네트워크 스택을 추상화한 인터페이스**이다.

Application이 **네트워크 내부 동작을 직접 다루지 않도록 만든 API**이다.

Socket은 **File 객체처럼 사용된다.**

예시

```

read()  
write()  
send()  
recv()

```

구조적으로 보면 다음과 같다.

```

Application  
↓  
Socket (인터페이스)  
↓  
Kernel TCP/IP Stack  
↓  
Network

```

즉

> **Socket은 User Space Application과 Kernel Network Stack 사이의 인터페이스이다.**

---

# 6. 핵심 정리

### 데이터 전달 흐름

```

Process → Socket → TCP/IP → Network → Host → Process

```

### 데이터 단위

| 계층 | 단위 |
|-----|------|
| Transport | Segment |
| Network | Packet |
| DataLink | Frame |

### Encapsulation

```

Data  
→ Segment (TCP Header)  
→ Packet (IP Header)  
→ Frame (MAC Header)

```

### Decapsulation

```

Frame 제거  
→ Packet 확인  
→ Segment 확인  
→ Process 전달

```

---

# 한 줄 정리
> 네트워크 데이터는 **Segment → Packet → Frame 순서로 캡슐화되어 전송되고, 목적지에서 역순으로 Decapsulation되어 Process에게 전달된다.**
