# 계층별 데이터 단위와 Segmentation

## 1. Socket에서 전송되는 데이터 단위

Application이 Socket을 통해 데이터를 전송할 때 사용하는 데이터 단위를 **Stream**이라고 한다.

### Stream의 특징
- 데이터는 **연속적인 바이트 흐름(Byte Stream)** 으로 전달된다.
- **시작점은 있지만 끝의 경계(boundary)가 명확하지 않다.**
- 메시지 단위가 아니라 **흐름 형태로 전달된다.**

예를 들어

```

Application → "HELLO"  
Application → "WORLD"

```

이렇게 두 번 보내도 수신 측에서는

```

HELLOWORLD

```

처럼 하나의 Stream으로 도착할 수 있다.

즉 TCP는 **메시지 기반이 아니라 Stream 기반 프로토콜**이다.

---

# 2. 계층별 데이터 최대 크기

네트워크 계층마다 **전송 가능한 최대 데이터 크기**가 존재한다.

| 계층 | 최대 단위 | 의미 |
|-----|-----------|------|
| L4 (Transport) | MSS | TCP가 한번에 보낼 수 있는 최대 데이터 |
| L3 (Network) | MTU | 네트워크에서 전송 가능한 최대 패킷 크기 |

---

# 3. MTU (Maximum Transmission Unit)

**MTU는 네트워크 계층에서 전송 가능한 최대 Packet 크기이다.**

일반적인 이더넷 환경

```

MTU = 1500 bytes

```

즉 **IP Packet 전체 크기가 1500 bytes를 넘을 수 없다.**

구성 예시

```

[ IP Header ] + [ TCP Header ] + [ Data ] ≤ 1500 bytes

```

---

# 4. MSS (Maximum Segment Size)

**MSS는 TCP가 한번에 보낼 수 있는 최대 Payload 크기이다.**

일반적으로

```

MSS = MTU - (IP Header + TCP Header)

```

예시

```

MTU = 1500  
IP Header = 20  
TCP Header = 20

MSS = 1500 - 40 = 1460 bytes

```

즉

```

TCP Payload 최대 크기 = 1460 bytes

```

---

# 5. 큰 데이터 전송 과정 (Segmentation)

Application에서 큰 데이터를 보내면 **TCP가 자동으로 분할한다.**

예시

```

Application Data = 4MB

```

이 데이터를 그대로 보내는 것이 아니라

```

4MB  
↓  
TCP Segmentation  
↓  
1460 bytes 단위 Segment 여러 개 생성  
↓  
각 Segment를 Packet으로 캡슐화  
↓  
Network 전송

```

즉

> 큰 데이터를 **MSS 단위로 분할하여 여러 개의 Segment로 전송**한다.

이 과정을 **Segmentation**이라고 한다.

---

# 6. 전체 데이터 흐름

```

Application  
↓  
Socket (Stream)  
↓  
TCP (Segmentation → MSS 단위)  
↓  
IP (Packet 생성 → MTU 제한)  
↓  
Frame 생성  
↓  
Network 전송

```

---

# 7. 핵심 정리

### Stream

```

Socket 데이터 단위  
→ Byte Stream  
→ 경계가 없음

```

### MSS

```

TCP Payload 최대 크기

```

### MTU

```

네트워크 Packet 최대 크기

```

### Segmentation

```

큰 데이터를 MSS 단위로 분할하여 전송

```

---

# 한 줄 정리

> Application의 Stream 데이터는 TCP에서 MSS 단위로 Segmentation 되고, IP에서는 MTU 제한에 맞게 Packet으로 전송된다.
