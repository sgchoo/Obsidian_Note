# Switch와 Switching 개념 정리

## Switch의 핵심 개념

Switch는 네트워크에서 패킷이나 프레임을 적절한 경로로 전달하는 중계 장치입니다. 이를 고속도로 시스템에 비유하면 다음과 같이 이해할 수 있습니다:

### 고속도로 비유를 통한 이해

```
네트워크 개념     →    고속도로 비유
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Packet          →    자동차
Switch          →    교차로 (인터체인지)
Routing Table   →    내비게이션 (경로 정보)
Switching       →    경로 선택 행위
Metric          →    경로 비용 (거리, 시간, 통행료)
```

**핵심 프로세스:** 자동차(Packet)가 교차로(Switch)를 만났을 때, 내비게이션(Routing Table)에 저장된 정보를 **근거**로 최적의 경로(Path)를 **선택(Switching)** 합니다.

## Switching의 정의

**Switching**은 수신한 데이터(패킷 또는 프레임)를 분석하여 목적지로 전달하기 위한 최적의 출력 포트를 결정하고 전송하는 과정입니다.

### Switching 프로세스

```
┌─────────────────────────────────────────────────┐
│  1. 패킷/프레임 수신                             │
│  2. 헤더 정보 분석 (목적지 주소 확인)             │
│  3. Switching Table/Routing Table 조회           │
│  4. 최적 경로 결정 (Metric 기반)                 │
│  5. 해당 포트로 전달                             │
└─────────────────────────────────────────────────┘
```

## Switch의 계층별 분류

OSI 7 Layer 모델에서 Switch는 동작하는 계층에 따라 분류됩니다:

### L2 Switch (Layer 2 Switch / Data Link Layer)

**동작 기준:** MAC 주소 (Media Access Control Address)

**특징:**

- 데이터 링크 계층(Layer 2)에서 동작
- 이더넷 프레임의 목적지 MAC 주소를 기반으로 Switching
- 같은 네트워크(브로드캐스트 도메인) 내에서 동작
- MAC Address Table (CAM Table)을 사용하여 포트 매핑

**주요 기능:**

- Frame Forwarding: MAC 주소 기반 프레임 전달
- MAC Learning: 송신자 MAC 주소 학습 및 테이블 갱신
- Flooding: 목적지를 모를 경우 모든 포트로 전송
- Filtering: 같은 세그먼트 내 트래픽 차단

**사용 예시:**

```
PC A (MAC: AA:AA:AA:AA:AA:AA)
    ↓
L2 Switch [MAC Address Table 조회]
    ↓
PC B (MAC: BB:BB:BB:BB:BB:BB)
```

### L3 Switch (Layer 3 Switch / Network Layer)

**동작 기준:** IP 주소 (Internet Protocol Address)

**특징:**

- 네트워크 계층(Layer 3)에서 동작
- IP 패킷의 목적지 IP 주소를 기반으로 Switching
- 서로 다른 네트워크(서브넷) 간 라우팅 가능
- Routing Table (FIB - Forwarding Information Base)을 사용

**주요 기능:**

- Packet Routing: IP 주소 기반 패킷 라우팅
- Inter-VLAN Routing: VLAN 간 통신 지원
- Access Control: ACL(Access Control List) 기반 접근 제어
- QoS: 트래픽 우선순위 관리

**사용 예시:**

```
Network A (192.168.1.0/24)
    ↓
L3 Switch [Routing Table 조회]
    ↓
Network B (192.168.2.0/24)
```

### L4-L7 Switch (Application Layer Switch)

**동작 기준:** 포트 번호, 애플리케이션 데이터

**특징:**

- 전송 계층(L4) 이상의 정보 활용
- 로드 밸런싱, 콘텐츠 기반 스위칭 수행
- 주로 Load Balancer, ADC(Application Delivery Controller)로 구현

**사용 예시:**

- HTTP/HTTPS 트래픽을 여러 웹 서버로 분산
- URL 패턴 기반 서버 선택

## Switching 계층 비교표

|구분|L2 Switch|L3 Switch|L4-L7 Switch|
|---|---|---|---|
|**동작 계층**|Data Link (Layer 2)|Network (Layer 3)|Transport ~ Application (Layer 4-7)|
|**판단 기준**|MAC 주소|IP 주소|포트 번호, 애플리케이션 데이터|
|**참조 테이블**|MAC Address Table|Routing Table|Session Table, Content Table|
|**주요 용도**|같은 네트워크 내 통신|네트워크 간 라우팅|로드 밸런싱, 트래픽 제어|
|**속도**|매우 빠름|빠름|상대적으로 느림|
|**지능성**|낮음|중간|높음|

## Metric: 경로 선택의 비용

Switching(특히 L3 라우팅)에서 **Metric**은 최적 경로를 결정하기 위한 **비용 값**입니다.

### Metric의 개념

```
목적지까지 가는 경로가 여러 개일 때:

경로 A: Metric = 10
경로 B: Metric = 20
경로 C: Metric = 5

→ Metric이 가장 낮은 경로 C를 선택
```

### Metric 결정 요소

라우팅 프로토콜에 따라 다양한 요소가 Metric 계산에 사용됩니다:

|요소|설명|예시|
|---|---|---|
|**Hop Count**|거쳐야 하는 라우터의 수|RIP (최대 15홉)|
|**Bandwidth**|링크의 대역폭|OSPF, EIGRP|
|**Delay**|전송 지연 시간|EIGRP|
|**Load**|링크의 현재 부하 상태|EIGRP|
|**Reliability**|링크의 신뢰성|EIGRP|
|**Cost**|관리자가 수동으로 설정한 비용|OSPF (Cost = 10^8 / Bandwidth)|

### Metric 계산 예시 (OSPF)

```
┌─────────┐         ┌─────────┐         ┌─────────┐
│Router A │────1────│Router B │────1────│Router C │
└─────────┘  100Mbps└─────────┘  100Mbps└─────────┘
     │                                        │
     │               10Mbps                   │
     └────────────────10──────────────────────┘

경로 1 (A → B → C): Cost = 1 + 1 = 2
경로 2 (A → C 직접): Cost = 10
→ 경로 1 선택 (Metric이 낮음)
```

## Routing Table의 구조

Routing Table은 Switch(Router)가 경로를 결정하는 데 사용하는 데이터베이스입니다.

### Routing Table 구성 요소

```
목적지 네트워크 | 서브넷 마스크 | Next Hop | 인터페이스 | Metric | 프로토콜
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
192.168.1.0   | 255.255.255.0 | 10.0.0.2 | eth0      | 10    | OSPF
10.0.0.0      | 255.255.255.0 | Directly | eth1      | 0     | Connected
0.0.0.0       | 0.0.0.0       | 10.0.0.1 | eth0      | 1     | Static
```

**주요 필드:**

- **목적지 네트워크**: 패킷이 도달해야 할 네트워크 주소
- **Next Hop**: 패킷을 전달할 다음 라우터의 IP 주소
- **인터페이스**: 패킷을 송출할 물리적/논리적 포트
- **Metric**: 해당 경로의 비용
- **프로토콜**: 경로 학습 방법 (Static, Dynamic, Connected 등)

## Switching 동작 흐름도

```
패킷 수신
    ↓
헤더 분석 (L2: MAC, L3: IP)
    ↓
테이블 조회 (MAC Table or Routing Table)
    ↓
    ┌─────────┐
    │목적지   │
    │존재?    │
    └────┬────┘
         │
    ┌────┴────┐
   Yes        No
    │          │
    ↓          ↓
Metric 비교  Flooding or
최적 경로 선택  Default Route
    │          │
    └────┬─────┘
         ↓
   출력 포트로 전송
         ↓
    전송 완료
```

## 핵심 개념 요약

1. **Switch**: 패킷/프레임을 적절한 경로로 전달하는 네트워크 장비
2. **Switching**: 수신한 데이터를 목적지로 전달하기 위한 경로 선택 과정
3. **L2 Switch**: MAC 주소 기반, 같은 네트워크 내 프레임 전달
4. **L3 Switch**: IP 주소 기반, 서로 다른 네트워크 간 패킷 라우팅
5. **Metric**: 경로 선택 시 사용하는 비용 값 (낮을수록 우선)
6. **Routing Table**: 경로 정보를 저장한 데이터베이스

## Router와 L3 Switch의 차이

실무에서 혼용되는 개념이지만, 전통적인 차이점은 다음과 같습니다:

|구분|Router|L3 Switch|
|---|---|---|
|**주요 기능**|네트워크 간 라우팅|고속 라우팅 + L2 스위칭|
|**처리 방식**|Software 기반 (CPU)|Hardware 기반 (ASIC)|
|**속도**|상대적으로 느림|매우 빠름|
|**포트 수**|적음 (수십 개)|많음 (수백 개)|
|**용도**|WAN 연결, 복잡한 라우팅|LAN 내 고속 라우팅|
|**추가 기능**|NAT, VPN, 방화벽 등 다양|VLAN, STP 등 스위칭 중심|

현대 네트워크 장비는 이러한 경계가 모호해지고 있으며, Multilayer Switch라는 용어로 통합되기도 합니다.

## 실무 적용 시나리오

### 시나리오 1: 소규모 사무실 네트워크

```
인터넷 ─ Router(L3) ─ L2 Switch ─ PC들
```

- Router: 인터넷 연결 및 NAT
- L2 Switch: 내부 PC 간 통신

### 시나리오 2: 중대규모 기업 네트워크

```
인터넷 ─ Edge Router ─ Core L3 Switch ─┬─ L2 Switch (부서 A)
                                       ├─ L2 Switch (부서 B)
                                       └─ L2 Switch (부서 C)
```

- Core L3 Switch: VLAN 간 라우팅, 고속 백본
- L2 Switch: 각 부서 내부 통신

### 시나리오 3: 데이터센터

```
인터넷 ─ L4-L7 Switch (Load Balancer)
            ↓
        L3 Switch (Distribution)
            ↓
        L2 Switch (Access) ─ Servers
```

- L4-L7 Switch: 부하 분산
- L3 Switch: 서버 간 라우팅
- L2 Switch: 서버 연결

## 참고: Switching 관련 주요 프로토콜

- **L2**: STP (Spanning Tree Protocol), VTP (VLAN Trunking Protocol)
- **L3**: RIP, OSPF, EIGRP, BGP (라우팅 프로토콜)
- **VLAN**: 802.1Q (가상 LAN 태깅)
