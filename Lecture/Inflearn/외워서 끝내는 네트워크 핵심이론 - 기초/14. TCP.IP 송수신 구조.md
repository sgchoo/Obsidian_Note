# TCP/IP 송수신 구조

## 1. 비유: 에펠탑을 택배로 보내기

파리의 에펠탑을 그대로 택배로 보낼 수는 없다.  
그래서 다음과 같은 과정을 거친다.

1. **분해** → 운송 가능한 크기로 나눈다 (MTU)
2. **운송** → 여러 개로 나누어 전달
3. **조립** → 목적지에서 다시 조립

TCP/IP 통신도 동일한 구조로 동작한다.

```

큰 데이터  
↓  
Segmentation (분해)  
↓  
Network 전송  
↓  
Reassembly (조립)

```

---

# 2. Sender 측 TCP/IP 송신 과정

데이터를 보내는 쪽(Sender)은 다음과 같은 과정을 거친다.

## 1️⃣ Process Buffer

Application(Process)는 먼저 보내고 싶은 데이터를 **Process 내부 Buffer**에 저장한다.

예

```

File → Process Buffer

```

---

## 2️⃣ Socket Buffer 복사

Application이 `send()`를 호출하면

데이터는 **Kernel의 Socket Send Buffer**로 복사된다.

```

Process Buffer  
↓ copy  
Socket Send Buffer (Kernel)

```

이 단계에서 **User Space → Kernel Space** 전환이 발생한다.

---

## 3️⃣ TCP Segmentation

TCP Layer는 Socket Buffer에 있는 데이터를 **MSS 단위로 분할한다.**

```

Application Data  
↓  
TCP Segmentation  
↓

Segment1  
Segment2  
Segment3

```

---

## 4️⃣ Sequence Number 부여

각 Segment에는 **Sequence Number**가 부여된다.

예

```

Segment1 → Seq = 0  
Segment2 → Seq = 1460  
Segment3 → Seq = 2920

```

이 번호를 통해

- 순서 보장
- 손실 탐지
- 재전송 관리

가 가능해진다.

---

## 5️⃣ Packet 및 Frame 생성

Segment는 아래와 같은 과정으로 캡슐화된다.

```

Segment  
↓ IP Header 추가  
Packet  
↓ MAC Header 추가  
Frame

```

즉

```

Segment → Packet → Frame

```

---

## 6️⃣ 네트워크 전송

Frame은 **NIC(Network Interface Card)** 를 통해 네트워크로 전송된다.

```

Sender  
↓  
NIC  
↓  
Network

```

---

# 3. Receiver 측 TCP/IP 수신 과정

수신 측에서는 송신 과정의 **역순**으로 처리된다.

---

## 1️⃣ Frame 수신

네트워크로부터 **Frame**을 수신한다.

```

Network  
↓  
NIC  
↓  
Frame 수신

```

---

## 2️⃣ Decapsulation

수신된 데이터는 계층별로 Header가 제거된다.

```

Frame  
↓ MAC 제거  
Packet  
↓ IP 제거  
Segment

```

---

## 3️⃣ TCP 재조립

TCP는 Segment의 **Sequence Number**를 확인하여

- 순서 정렬
- 데이터 재조립

을 수행한다.

```

Segment1  
Segment3  
Segment2

```

↓

```

Segment1  
Segment2  
Segment3

```

---

## 4️⃣ Socket Receive Buffer 저장

재조립된 데이터는 **Socket Receive Buffer**에 저장된다.

```

TCP  
↓  
Socket Receive Buffer

```

---

## 5️⃣ Process Buffer 전달

Application(Process)이 `read()` 또는 `recv()`를 호출하면

데이터는 **Process Buffer로 복사된다.**

```

Socket Buffer  
↓ copy  
Process Buffer

```

---

# 4. Flow Control (Window Size)

Receiver는 자신의 **Buffer 여유 공간**을 Sender에게 알려준다.

이를 **Window Size**라고 한다.

예

```

Receive Buffer = 64KB  
사용 중 = 20KB

Window Size = 44KB

```

Sender는 이 Window Size 범위 내에서만 데이터를 보낼 수 있다.

---

# 5. ACK (Acknowledgement)

Receiver는 데이터를 정상적으로 받으면 **ACK**를 보낸다.

ACK는

```

다음에 받아야 할 Sequence Number

```

를 의미한다.

예

```

Seq 0 → OK  
Seq 1460 → OK  
Seq 2920 → OK

```

Receiver는

```

ACK = 4380

```

을 보낸다.

즉

> **4380까지 정상 수신, 다음 데이터는 4380부터 보내라**

는 의미다.

---

# 6. TCP 통신 반복 구조

TCP 통신은 다음 구조를 반복한다.

```

Sender  
↓  
Segment 전송  
↓  
Receiver  
↓  
ACK 전송  
↓  
Sender

```

즉

```

Data → ACK → Data → ACK

```

형태로 지속적으로 통신한다.

---

# 7. 네트워크에서 흔한 장애 유형

## 1️⃣ Packet Loss (패킷 유실)

패킷이 네트워크 중간에서 사라지는 현상

원인

- 네트워크 혼잡
- 라우터 버퍼 부족
- 링크 오류

---

## 2️⃣ Retransmission + Duplicate ACK

Receiver가 같은 ACK를 여러 번 보내면

Sender는 **패킷 손실로 판단**하고 재전송한다.

예

```

ACK 1000  
ACK 1000  
ACK 1000

```

→ **Fast Retransmit 발생**

원인

- Network 문제
- Endpoint 처리 지연

---

## 3️⃣ Out of Order

패킷이 순서가 바뀌어 도착하는 현상

예

```

Packet1  
Packet3  
Packet2

```

원인

- 라우팅 경로 차이
- 네트워크 혼잡

TCP는 Sequence Number로 정렬한다.

---

## 4️⃣ Zero Window

Receiver Buffer가 가득 찬 상태

```

Window Size = 0

```

Sender는 더 이상 데이터를 보낼 수 없다.

원인

- Application이 데이터를 읽지 않음
- Endpoint 성능 문제

```

💡 참고로 지금 네 강의 흐름을 보면 다음에 **거의 반드시 나오는 개념**이 하나 있어:

```
TCP Sliding Window
```

아까 강의에서 나온 **Window Size**는 사실 이 **Sliding Window 알고리즘**의 일부야.

이거 이해하면

- 왜 ACK가 누적 ACK인지
    
- 왜 throughput이 결정되는지
    
- 왜 TCP 성능이 Window에 좌우되는지
    

가 한 번에 연결돼.

원하면 다음 강의 정리 가져오면 **그것도 같은 스타일로 정리해줄게.**
