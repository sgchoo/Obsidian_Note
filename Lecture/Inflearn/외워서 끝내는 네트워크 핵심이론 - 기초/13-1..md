# Segmentation vs Fragmentation

네트워크에서 큰 데이터를 전송할 때 데이터는 **여러 개로 나뉘어 전송**된다.

이때 사용하는 두 가지 방식이 있다.

- **Segmentation (세그멘테이션)**
- **Fragmentation (프래그멘테이션)**

이 둘은 **데이터를 분할한다는 점은 같지만 수행하는 계층이 다르다.**

| 구분 | Segmentation | Fragmentation |
|-----|-------------|--------------|
| 계층 | L4 (Transport) | L3 (Network) |
| 기준 | MSS | MTU |
| 수행 주체 | TCP | IP |
| 목적 | TCP 전송을 위한 분할 | 네트워크 전송 크기 제한 해결 |

---

# 1. Segmentation

Segmentation은 **Transport Layer(TCP)** 에서 발생한다.

Application에서 큰 데이터를 보내면 TCP가 이를 **MSS 단위로 분할**한다.

예시

```

Application Data = 4MB

```

TCP는 이를

```

1460 bytes  
1460 bytes  
1460 bytes  
...

```

와 같이 **여러 개의 Segment로 분할**한다.

### 특징

- TCP에서 발생
- MSS 기준으로 분할
- 각 Segment는 **Sequence Number**를 가진다
- 수신 측에서 **순서대로 재조립(Reassembly)** 한다

---

# 2. Fragmentation

Fragmentation은 **Network Layer(IP)** 에서 발생한다.

Packet이 네트워크의 **MTU보다 크면 IP가 강제로 분할한다.**

예시

```

Packet Size = 2000 bytes  
MTU = 1500 bytes

```

이 경우

```

1500 bytes  
500 bytes

```

로 **IP Packet이 분할된다.**

### 특징

- IP 계층에서 발생
- MTU 기준으로 분할
- Router에서 발생 가능
- 수신 Host에서 재조립

---

# 3. Segmentation vs Fragmentation 흐름

```

Application  
↓  
Socket (Stream)  
↓  
TCP Segmentation (MSS 기준)  
↓  
IP Packet 생성  
↓  
MTU 초과 시 Fragmentation 발생  
↓  
Network 전송

```

즉

```

Segmentation → TCP에서 분할  
Fragmentation → IP에서 분할

```

---

# 4. 왜 Fragmentation을 피하려 할까?

Fragmentation이 발생하면 다음 문제가 생긴다.

- Router가 추가 작업 수행
- 패킷 손실 시 전체 재전송 가능성 증가
- 네트워크 성능 저하

그래서 실제 네트워크에서는

> **TCP가 MSS를 MTU보다 작게 설정하여 Fragmentation을 최대한 피한다.**

---

# 핵심 정리

```

Segmentation  
→ TCP에서 MSS 기준으로 분할

Fragmentation  
→ IP에서 MTU 기준으로 분할

```

---

# 한 줄 정리

> TCP는 MSS 기준으로 Segmentation을 수행하고, MTU를 초과하는 Packet이 발생하면 IP 계층에서 Fragmentation이 발생한다.(면접에서도 진짜 많이 묻는 부분이다.)
