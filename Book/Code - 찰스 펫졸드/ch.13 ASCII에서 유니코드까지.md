# Chapter 13: ASCII에서 유니코드까지 (From ASCII to Unicode)

## 📌 핵심 개념

### 초기 부호 체계: 보도 부호 (Baudot Code)
- **초기에는 5비트를 사용하는 부호 체계**로 보도 부호를 사용
- 5비트 = 2^5 = 32가지 문자만 표현 가능
- **소문자와 대문자를 구분하지 못한다**

### 제어 문자의 등장
- **보도 부호에서 캐리지 리턴과 줄 바꿈을 사용**했다
- 텍스트 형식 제어를 위한 특수 문자 필요성 인식

### ASCII의 개발
- **2번째의 문제로 인해 모든 것을 표현할 수 있는 부호는 7비트가 필요**하다는 것을 깨닫고, **"ASCII"가 개발**되었다
- 7비트 = 2^7 = 128개 문자 표현 가능
- 영어 알파벳, 숫자, 특수문자, 제어문자 모두 포함

### ASCII의 한계와 유니코드의 등장
- **그러나 다른 언어의 강세 표시, 한/중/일 언어를 표현하지 못했는데, 이는 "유니코드"가 개발되어 해결**했다
- 전 세계 모든 문자를 표현할 수 있는 통합 문자 집합

### 인코딩의 중요성
- **이러한 언어 포맷을 잘못 설정한다면, 같은 문장이 다르게 해석될 수도 있다**
- 인코딩 방식에 따른 문자 깨짐 현상 발생

## 🔍 추가 설명

### 보도 부호 (Baudot Code) 상세
```
5비트 구조 (32가지):
- 26개 알파벳
- 숫자와 특수문자는 시프트 문자로 전환
- LTRS (Letters) 모드와 FIGS (Figures) 모드 전환

한계:
- 소문자/대문자 구분 불가
- 제한된 특수문자
- 복잡한 시프트 메커니즘
```

### ASCII (American Standard Code for Information Interchange)
```
7비트 구조 (128개 문자):

제어문자 (0-31):
- 00: NULL
- 08: Backspace  
- 09: Tab
- 0A: Line Feed (LF)
- 0D: Carriage Return (CR)
- 1B: Escape

인쇄 가능한 문자 (32-126):
- 32: Space
- 48-57: 숫자 0-9
- 65-90: 대문자 A-Z
- 97-122: 소문자 a-z
- 기타 특수문자

127: DELETE
```

### ASCII 확장 (8비트)
```
Extended ASCII (128-255):
- 서유럽 언어의 악센트 문자
- 그래픽 문자
- 수학 기호

문제점:
- 지역별로 다른 확장 방식
- 호환성 문제 발생
```

### 유니코드의 발전
```
유니코드 버전별 확장:
- Unicode 1.0 (1991): 65,536 문자 (16비트)
- Unicode 2.0 (1996): 서로게이트 페어 도입
- Unicode 3.0 (1999): 49,194 문자
- Unicode 13.0 (2020): 143,859 문자
- Unicode 15.1 (2023): 149,813 문자

포함 언어:
- 라틴 문자 (영어, 유럽어)
- 한중일 통합 한자 (CJK)
- 아랍 문자
- 인도 계열 문자
- 이모지 및 기호
```

### 유니코드 인코딩 방식
```
UTF-8 (가변 길이):
- 1바이트: ASCII 호환 (0-127)
- 2바이트: 서유럽, 아랍어 등
- 3바이트: 한중일 문자
- 4바이트: 이모지, 고대 문자

UTF-16 (가변 길이):
- 2바이트 또는 4바이트
- Windows 내부 표준

UTF-32 (고정 길이):
- 4바이트 고정
- 메모리 사용량 많음
```

### 프로그래밍에서의 문자 처리
```python
# Python 예시
text = "Hello 한글 🌟"
print(text.encode('utf-8'))     # b'Hello \xed\x95\x9c\xea\xb8\x80 \xf0\x9f\x8c\x9f'
print(text.encode('cp949'))     # b'Hello \xc7\xd1\xb1\xdb ?'  # 이모지 오류
print(len(text))                # 9 (문자 개수)
print(len(text.encode('utf-8'))) # 14 (바이트 수)
```

## 🔧 문자 코드 변환 예시

### ASCII 변환
```
문자 'A' = 65 (decimal) = 41 (hex) = 01000001 (binary)
문자 'a' = 97 (decimal) = 61 (hex) = 01100001 (binary)
문자 '0' = 48 (decimal) = 30 (hex) = 00110000 (binary)
```

### 유니코드 변환
```
한글 '가': U+AC00 (유니코드)
UTF-8 인코딩: EA B0 80 (3바이트)
UTF-16 인코딩: AC 00 (2바이트)

이모지 '😀': U+1F600 (유니코드)  
UTF-8 인코딩: F0 9F 98 80 (4바이트)
UTF-16 인코딩: D8 3D DE 00 (4바이트, 서로게이트 페어)
```

## 🚨 주의사항

### 인코딩 관련 문제점
1. **BOM (Byte Order Mark)**: UTF-16, UTF-32에서 바이트 순서 표시
2. **정규화**: 같은 문자의 다른 표현 방식 (NFD, NFC)
3. **크기 제한**: 일부 시스템의 문자열 길이 제한
4. **호환성**: 레거시 시스템과의 호환성 문제

## 📝 핵심 포인트
1. **진화 과정**: 보도 부호(5비트) → ASCII(7비트) → 유니코드(가변)
2. **ASCII의 혁신**: 대소문자 구분과 제어문자 포함으로 현대 텍스트 처리의 기초
3. **유니코드의 필요성**: 전 세계 문자를 통합하여 국제화 문제 해결
4. **인코딩의 중요성**: 올바른 인코딩 설정이 텍스트 처리의 핵심
5. **호환성**: UTF-8이 ASCII와 호환되면서도 전 세계 문자 지원
