# Code - Chapter 5: Around the Block (공통 기준과 회로 최적화)

## 📖 개요

Chapter 5에서는 브레일 점자를 전기적으로 구현하면서 회로 설계의 효율성과 공통 기준점(접지)의 중요성을 다룹니다. 이는 현대 컴퓨터 시스템의 공통 핸들러 테이블과 같은 설계 원리의 기초가 됩니다.

## ⚡ 전기 회로의 최적화

### 기본 브레일 회로의 문제점

초기 브레일 전기 구현에서는 각 점마다 독립적인 회로가 필요:

```
점 1: 건전지1 ─ 스위치1 ─ 전구1
점 2: 건전지2 ─ 스위치2 ─ 전구2
점 3: 건전지3 ─ 스위치3 ─ 전구3
...
점 6: 건전지6 ─ 스위치6 ─ 전구6
```

**문제점:**

- 많은 건전지와 전선 필요
- 복잡하고 비효율적인 구조
- 유지보수 어려움

### 공통 기준점의 도입

**점자를 연결해서 불필요한 전선을 없애거나, 위험한 것들을 공통 매개체인 땅(지구)에 흘려보냄**

```
최적화된 회로:
           +전압
             │
    ┌────────┼────────┬────────┐
    │        │        │        │
 스위치1   스위치2   스위치3   ...
    │        │        │        │
  전구1    전구2    전구3    ...
    │        │        │        │
    └────────┼────────┴────────┘
           접지 (땅)
```

## 🌍 접지(Ground)의 개념과 중요성

### 접지란?

- **공통 기준점**: 모든 회로가 참조하는 0V 기준
- **안전장치**: 위험한 전압을 안전하게 방출
- **신호 안정성**: 노이즈 감소와 신호 품질 향상

### 공통 매개체로서의 지구

```
개별 연결 방식:
노드A ←→ 노드B
노드A ←→ 노드C  
노드B ←→ 노드C
(3개 노드 = 3개 연결)

공통 기준 방식:
노드A → 지구 ← 노드B
노드C → 지구
(3개 노드 = 1개 공통 기준)
```

### 통신에서의 공통 기준

**두 노드는 공통 매개체를 참조하여 통신함**

- 개별 점대점 연결 대신 공통 버스 사용
- 효율적인 자원 활용
- 확장성과 유지보수성 향상

## 💻 현대 컴퓨터 시스템의 공통 핸들러

### CPU 인터럽트 테이블

**CPU 공통 인터럽트 테이블**

```
인터럽트 벡터 테이블 (IVT):
┌─────────┬──────────────────┐
│ 번호    │ 핸들러 주소      │
├─────────┼──────────────────┤
│ 0x00    │ 0xFF000000      │ ← 타이머 인터럽트
│ 0x01    │ 0xFF000100      │ ← 키보드 인터럽트  
│ 0x02    │ 0xFF000200      │ ← 마우스 인터럽트
│ ...     │ ...             │
└─────────┴──────────────────┘
```

**공통 기준의 이점:**

- 모든 하드웨어가 같은 테이블 참조
- 새로운 장치 추가 시 테이블에만 등록
- 운영체제가 중앙 집중식 관리

### 시스템 콜 테이블

**CPU 공통 시스템 콜 테이블**

```
시스템 콜 디스패치 테이블:
┌─────────┬──────────────────┐
│ 번호    │ 함수 포인터      │
├─────────┼──────────────────┤
│ 1       │ sys_read()      │
│ 2       │ sys_write()     │
│ 3       │ sys_open()      │
│ 4       │ sys_close()     │
│ ...     │ ...             │
└─────────┴──────────────────┘
```

**동작 방식:**

```assembly
; 시스템 콜 호출
mov eax, 1        ; 시스템 콜 번호 (sys_read)
mov ebx, fd       ; 파일 디스크립터
mov ecx, buffer   ; 버퍼 주소
mov edx, count    ; 읽을 바이트 수
int 0x80          ; 공통 인터럽트로 커널 진입
```

### 기타 공통 핸들러 테이블들

#### 1. 가상 함수 테이블 (VTable)

```cpp
class Animal {
    virtual void speak() = 0;
};

// VTable (공통 함수 포인터 테이블)
┌──────────────┬─────────────┐
│ Animal::speak│ 구현체 주소 │
├──────────────┼─────────────┤
│ Dog::speak   │ 0x12345678  │
│ Cat::speak   │ 0x87654321  │
└──────────────┴─────────────┘
```

#### 2. 네트워크 프로토콜 핸들러

```
패킷 타입별 핸들러 테이블:
┌─────────┬──────────────────┐
│ 프로토콜│ 처리 함수        │
├─────────┼──────────────────┤
│ TCP     │ tcp_handler()    │
│ UDP     │ udp_handler()    │
│ ICMP    │ icmp_handler()   │
└─────────┴──────────────────┘
```

#### 3. 디바이스 드라이버 테이블

```
장치별 드라이버 테이블:
┌─────────┬──────────────────┐
│ 장치 ID │ 드라이버 구조체  │
├─────────┼──────────────────┤
│ 0x1234  │ nvidia_driver    │
│ 0x5678  │ intel_driver     │
│ 0x9ABC  │ amd_driver       │
└─────────┴──────────────────┘
```

## 🔗 설계 원리의 연관성

### 회로 설계 → 시스템 설계

```
전기 회로의 접지     →    컴퓨터의 공통 테이블
├ 공통 기준점       →    ├ 중앙 집중식 관리
├ 자원 절약        →    ├ 메모리 효율성
├ 확장 용이성      →    ├ 모듈러 설계
└ 안전성 향상      →    └ 오류 처리 일원화
```

### 공통 매개체의 이점

#### 1. 효율성 (Efficiency)

- **하드웨어**: 전선과 건전지 수 감소
- **소프트웨어**: 메모리와 CPU 사용량 최적화

#### 2. 확장성 (Scalability)

- **하드웨어**: 새로운 점 추가 시 기존 구조 유지
- **소프트웨어**: 새로운 기능 추가 시 테이블에만 등록

#### 3. 유지보수성 (Maintainability)

- **하드웨어**: 중앙 집중식 전원 관리
- **소프트웨어**: 중앙 집중식 핸들러 관리

#### 4. 안정성 (Reliability)

- **하드웨어**: 접지를 통한 안전 보장
- **소프트웨어**: 공통 오류 처리 메커니즘

```

```

```
상품 테이블 → 카테고리 ID → 카테고리 테이블 (공통 참조)
```
