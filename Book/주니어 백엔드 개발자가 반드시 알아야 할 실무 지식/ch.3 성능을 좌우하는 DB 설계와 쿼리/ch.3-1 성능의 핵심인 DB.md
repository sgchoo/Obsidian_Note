# 3-1. 성능에 핵심인 DB

## 핵심 포인트

### 성능 문제의 주요 원인

- 성능에 문제가 있다면 **DB 조회를 의심**할 법하다

### 문제의 본질

- DB 자체의 문제보다는 **"풀스캔"** 등의 DB를 잘못 사용하는 경우가 많다

## DB 성능 문제 진단

### 1. 우선 확인사항

✅ DB 조회가 성능 병목의 주요 원인임을 인지

### 2. 흔한 문제 패턴

#### ❌ DB를 잘못 사용하는 경우
- **풀스캔(Full Scan)**: 인덱스 없이 전체 테이블을 스캔
- 불필요한 조인
- N+1 쿼리 문제
- 비효율적인 쿼리 구조

#### ✅ 실제 DB 자체 문제는 드물다
- 대부분 쿼리 최적화로 해결 가능
- DB 설정이나 하드웨어 문제는 상대적으로 적음

## 해결 방향

### 1. 쿼리 최적화
- 적절한 인덱스 생성
- 쿼리 실행 계획 분석
- 불필요한 데이터 조회 제거

### 2. DB 사용 패턴 개선
- 풀스캔 방지
- 효율적인 조인 전략
- 배치 처리 활용

## 💡 기억할 점

> **"DB 자체의 문제보다는 DB를 잘못 사용하는 경우가 많다"**
> 
> 성능 문제 발생 시, DB 교체나 스펙 업그레이드보다 **쿼리 최적화와 올바른 사용법**을 먼저 검토하자
