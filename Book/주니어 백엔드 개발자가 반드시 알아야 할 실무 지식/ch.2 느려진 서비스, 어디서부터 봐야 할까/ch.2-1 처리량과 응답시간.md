# 서버 성능 관리

## 1. 코딩과 DB 연결 관리

### DB 커넥션 풀 관리

- DB 커넥션 풀을 제대로 반환하지 않으면 연결할 자원(커넥션 풀)이 없어 DB 오류가 발생
- 커넥션 최대 연결시간 관리가 중요

## 2. 처리량과 응답시간

### 2.1 성능 지표

서버 성능을 판단하는 다양한 지표들:

- 네트워크 속도
- 디스크 속도
- 메모리 크기
- 디바이스의 CPU 속도

**핵심 지표**: 응답시간과 처리량

### 2.2 응답시간 측정

데이터 특성과 네트워크 환경을 고려하여 적절한 측정 방식 선택

#### 측정 방식

1. **TTFB (Time to First Byte)**
    - 응답 데이터 중 첫 번째 바이트가 도착한 시간
    - 초기 응답 속도 평가에 유용

2. **TTLB (Time to Last Byte)**
    - 마지막 바이트가 도착한 시간
    - 전체 응답 완료 시간 평가

#### 서버 개발자 관점

- 주로 서버의 처리시간으로 응답시간 확인
    - 외부 API 호출
    - 내부 API 호출
    - DB SQL 실행
    - 기타 처리 로직

> 💡 **주의**: API 호출과 DB SQL 실행 시간이 큰 비중을 차지 (특히 외부 API)

### 2.3 처리량 측정

#### 측정 단위
- **TPS (Transaction Per Second)**: 초당 트랜잭션 수
- **RPS (Request Per Second)**: 초당 요청 수

#### 성능 임계점
- 최대 TPS 이상의 요청이 들어오면 응답시간 증가
- 병목 현상 발생 가능

### 2.4 성능 개선 방법

응답시간을 줄이기 위한 2가지 접근법:

1. **동시 처리 능력 향상**
    - 서버가 동시에 처리할 수 있는 요청 수 늘리기
    - 스레드 풀 크기 조정
    - 서버 스케일 아웃
    
2. **처리 시간 단축**
    - 처리 시간 자체를 줄이기
    - 코드 최적화
    - 캐싱 적용
    - DB 쿼리 최적화

### 2.5 모니터링

- TPS 확인을 위해 모니터링 도구 활용 필수
- 실시간 성능 추적 및 분석
- 병목 지점 파악 및 개선점 도출

## 핵심 요약

✅ DB 커넥션 풀 관리는 기본  
✅ 응답시간(TTFB/TTLB)과 처리량(TPS/RPS)이 주요 성능 지표  
✅ 외부 API와 DB SQL이 주요 병목 지점  
✅ 성능 개선은 동시 처리 능력 향상 + 처리 시간 단축  
✅ 지속적인 모니터링으로 성능 관리
