# 점진적 부하 증가 방식의 성능 테스트

## 1. 기본 방식

성능 테스트를 진행하는 가장 일반적인 방식은 **낮은 부하에서 시작해 점진적으로 부하를 높여가는 것**이다. 처음부터 목표 트래픽이나 최대치를 바로 걸지 않고, 단계적으로 동시 사용자 수(혹은 RPS)를 증가시키며 그때그때의 처리량과 응답 시간을 관찰한다.

이렇게 단계적으로 진행하는 이유는 다음과 같다.

- 부하 증가에 따른 성능 변화 곡선 전체를 관찰할 수 있음
- 시스템이 무너지기 시작하는 지점을 사전에 감지하고 대응할 수 있음
- 특정 부하 구간에서만 나타나는 병목(예: 커넥션 풀 고갈, 특정 캐시 미스율 상승)을 구간별로 특정할 수 있음

---

## 2. 부하-처리량 곡선의 3단계

부하를 점진적으로 높이면 처리량은 다음과 같은 패턴으로 변화한다.

### 2.1 선형 증가 구간

낮은 부하 구간에서는 부하가 늘어난 만큼 처리량도 거의 비례해서 증가한다. 시스템 자원에 아직 여유가 있어 요청이 대기 없이 바로 처리되는 상태.

### 2.2 포화점 (Saturation Point)

부하를 계속 높이면 어느 순간부터 처리량의 증가 폭이 둔화되기 시작한다. 이는 CPU, DB 커넥션, 스레드 풀 등 특정 자원이 한계에 가까워지면서 요청이 대기하기 시작했다는 신호다.

- **포화점 = 성능이 꺾이기 직전, 시스템이 낼 수 있는 최대 처리량 지점**
- 이 지점을 넘어서면 부하를 더 늘려도 처리량은 더 이상 비례해서 늘지 않고, 오히려 응답 시간이 눈에 띄게 증가하기 시작함
- 용량 계획(Capacity Planning) 관점에서 가장 중요하게 보는 지표 중 하나

### 2.3 버클존 (Buckle Zone)

포화점을 지나 부하를 계속 증가시키면 진입하는 구간으로, 처리량과 응답 시간이 함께 급격히 저하되는 구간이다.

- 이름 그대로 시스템이 하중을 버티지 못하고 "휘어지는(buckle)" 단계
- 처리량이 정체되는 수준을 넘어 **오히려 감소**하는 경우가 많음 (Retrograde, 역행 구간)
    - 원인: 대기 큐 적체로 인한 타임아웃/재시도 폭증, GC 급증, 커넥션 재시도로 인한 부하 가중 등 연쇄적 악화(Cascading Failure)
- 응답 시간은 기하급수적으로 증가하며, 에러율도 함께 급등하는 것이 일반적
- 실 서비스에서는 이 구간에 진입하지 않도록 임계치 이전에 오토스케일링, 서킷 브레이커, 레이트 리미팅 등으로 방어하는 것이 목표

## 3. 곡선 형태 요약

```
처리량
  ^
  |                 포화점
  |            ┌───●
  |          ／      ＼
  |        ／           ＼   ← 버클존 (처리량 급감, 응답시간 급증)
  |      ／                ＼
  |    ／
  |  ／  ← 선형 증가 구간
  +───────────────────────────> 부하(동시 사용자 수 / RPS)
```

- **선형 증가 구간**: 부하 ∝ 처리량
- **포화점**: 처리량 증가율이 꺾이는 변곡점, 최대 처리량 지점
- **버클존**: 포화점 이후, 처리량 정체~감소 + 응답 시간 급증이 동시에 발생하는 구간

---

## 4. 테스트 판정 기준

- **포화점이 목표 성능(목표 트래픽 기준 처리량/응답 시간 SLA)보다 높게 나온다면** → 시스템이 목표치를 만족하는 것으로 판단하고 테스트를 성공적으로 마무리할 수 있음
- **포화점이 목표 성능보다 낮다면** → 목표 트래픽에 도달하기 전에 이미 성능 저하가 시작된다는 의미이므로, 병목 구간을 특정해 개선 후 재테스트 필요
- 단순히 "죽었는가/살았는가"가 아니라, **포화점의 위치 자체가 곧 시스템의 실질적인 용량(Capacity)**이라는 점이 이 방식의 핵심

---

## 5. 실무 적용 팁

- 포화점 부근에서는 부하 증가 간격을 촘촘하게 잡아야 변곡점을 정확히 잡아낼 수 있음 (예: 초반엔 큰 단위로 증가시키다가, 처리량 증가율이 둔화되는 시점부터는 세밀하게 조정)
- 포화점과 버클존 진입 지점을 함께 기록해두면, 이후 오토스케일링 트리거 임계치나 레이트 리미팅 기준값을 설정하는 데 직접적인 근거로 활용 가능
- 이 방식은 앞서 정리한 **부하 테스트 / 스트레스 테스트**와 밀접하게 연결됨: 부하 테스트가 "포화점 이전 구간에서의 안정성"을 보는 것이라면, 스트레스 테스트는 "포화점을 지나 버클존까지 의도적으로 밀어붙여 한계와 실패 양상을 관찰"하는 것에 해당함
