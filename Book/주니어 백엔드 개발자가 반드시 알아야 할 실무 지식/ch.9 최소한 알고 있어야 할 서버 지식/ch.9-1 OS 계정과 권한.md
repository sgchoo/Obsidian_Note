# OS 계정과 권한

## 1. root 계정

`root` 계정은 리눅스/유닉스 계열 OS에서 가장 높은 권한을 가진 관리자 계정이다.

root 계정은 시스템의 모든 파일, 프로세스, 설정에 접근할 수 있으며 다음과 같은 작업을 수행할 수 있다.

- 시스템 설정 변경
- 사용자 계정 생성 및 삭제
- 파일 권한 변경
- 패키지 설치 및 삭제
- 서비스 실행 및 중지
- 시스템 종료 및 재부팅

root 계정은 모든 작업이 가능하기 때문에 보안상 매우 민감하다.  
따라서 root 계정에 직접 접근할 수 있는 인원은 최소화해야 한다.

일반적으로는 root 계정으로 직접 로그인하기보다, 일반 사용자 계정으로 로그인한 뒤 필요한 경우에만 `sudo` 명령어를 사용해 관리자 권한을 일시적으로 사용하는 방식이 권장된다.

---

## 2. 최소 권한 원칙

OS 보안에서 중요한 원칙 중 하나는 **최소 권한 원칙**이다.

최소 권한 원칙이란 사용자나 프로그램에게 필요한 만큼의 권한만 부여하는 것을 의미한다.

예를 들어, 특정 사용자가 로그 파일만 확인하면 되는 상황이라면 관리자 권한 전체를 부여하는 것이 아니라 해당 로그 파일을 읽을 수 있는 권한만 부여하는 것이 좋다.

불필요하게 높은 권한을 부여하면 다음과 같은 문제가 발생할 수 있다.

- 실수로 중요한 시스템 파일을 삭제할 수 있다.
- 악성 코드가 높은 권한으로 실행될 수 있다.
- 계정 탈취 시 피해 범위가 커진다.
- 권한 오남용으로 인해 시스템 안정성이 떨어질 수 있다.

---

## 3. 파일 권한 구조

리눅스에서 파일 권한은 보통 다음과 같은 형태로 표시된다.

```bash
-rwxr--r--
```

각 문자의 의미는 다음과 같다.

```text
-   rwx   r--   r--
│   │     │     │
│   │     │     └─ 다른 사용자(other)의 권한
│   │     └─────── 그룹(group)의 권한
│   └───────────── 소유자(user)의 권한
└───────────────── 파일 종류
```

첫 번째 문자는 파일의 종류를 의미한다.

|표시|의미|
|---|---|
|`-`|일반 파일|
|`d`|디렉터리|
|`l`|심볼릭 링크|

그 뒤 9자리는 3개씩 나누어 권한을 표시한다.

|구분|의미|
|---|---|
|앞 3글자|소유자의 권한|
|중간 3글자|그룹의 권한|
|마지막 3글자|다른 사용자의 권한|

권한 문자는 다음 의미를 가진다.

|권한|의미|
|---|---|
|`r`|읽기 권한|
|`w`|쓰기 권한|
|`x`|실행 권한|

예를 들어 다음 권한을 보자.

```bash
-rwxr--r--
```

이 권한은 다음과 같이 해석할 수 있다.

|대상|권한|의미|
|---|---|---|
|소유자|`rwx`|읽기, 쓰기, 실행 가능|
|그룹|`r--`|읽기만 가능|
|다른 사용자|`r--`|읽기만 가능|

---

## 4. 파일과 디렉터리에서 권한의 의미 차이

파일과 디렉터리에서 `r`, `w`, `x` 권한의 의미는 조금 다르다.

### 파일 권한

|권한|의미|
|---|---|
|`r`|파일 내용을 읽을 수 있음|
|`w`|파일 내용을 수정할 수 있음|
|`x`|파일을 실행할 수 있음|

### 디렉터리 권한

|권한|의미|
|---|---|
|`r`|디렉터리 안의 파일 목록을 볼 수 있음|
|`w`|디렉터리 안에 파일을 생성, 삭제, 이름 변경할 수 있음|
|`x`|디렉터리 안으로 접근할 수 있음|

디렉터리에서 `x` 권한은 특히 중요하다.  
디렉터리에 `x` 권한이 없으면 해당 디렉터리 안으로 이동하거나 내부 파일에 접근할 수 없다.

## 5. chmod 명령어

`chmod` 명령어는 파일이나 디렉터리의 권한을 변경할 때 사용한다.

```bash
chmod [권한] [파일명]
```

예를 들어 `run.sh` 파일에 실행 권한을 추가하려면 다음과 같이 입력한다.

```bash
chmod u+x run.sh
```

여기서 `u+x`는 소유자에게 실행 권한을 추가한다는 의미이다.

|기호|의미|
|---|---|
|`u`|소유자(user)|
|`g`|그룹(group)|
|`o`|다른 사용자(other)|
|`a`|전체 사용자(all)|
|`+`|권한 추가|
|`-`|권한 제거|
|`=`|권한을 정확히 지정|

예시는 다음과 같다.

```bash
chmod u+x run.sh
chmod g-w config.yml
chmod o-r secret.txt
chmod a+r README.md
```

---

## 6. 숫자로 권한 지정하기

`chmod`는 숫자로도 권한을 지정할 수 있다.

각 권한은 다음 숫자로 표현한다.

|권한|숫자|
|---|---|
|`r`|4|
|`w`|2|
|`x`|1|

권한은 숫자의 합으로 계산한다.

|숫자|권한|의미|
|---|---|---|
|7|`rwx`|읽기, 쓰기, 실행|
|6|`rw-`|읽기, 쓰기|
|5|`r-x`|읽기, 실행|
|4|`r--`|읽기|
|0|`---`|권한 없음|

예를 들어 다음 명령어는 소유자에게 모든 권한을 주고, 그룹과 다른 사용자에게는 읽기와 실행 권한만 부여한다.

```bash
chmod 755 run.sh
```

`755`는 다음과 같이 해석된다.

|대상|숫자|권한|
|---|---|---|
|소유자|7|`rwx`|
|그룹|5|`r-x`|
|다른 사용자|5|`r-x`|

또 다른 예시는 다음과 같다.

```bash
chmod 644 config.yml
```

`644`는 다음과 같다.

|대상|숫자|권한|
|---|---|---|
|소유자|6|`rw-`|
|그룹|4|`r--`|
|다른 사용자|4|`r--`|

## 7. 777 권한의 위험성

다음 명령어는 소유자, 그룹, 다른 사용자 모두에게 모든 권한을 부여한다.

```bash
chmod 777 file.txt
```

`777`은 다음을 의미한다.

```text
rwxrwxrwx
```

즉, 모든 사용자가 해당 파일을 읽고, 수정하고, 실행할 수 있다.

이는 보안상 매우 위험할 수 있다.  
특히 서버 환경에서 설정 파일, 실행 파일, 업로드 디렉터리 등에 무분별하게 `777` 권한을 부여하면 다음 문제가 발생할 수 있다.

- 다른 사용자가 중요한 파일을 수정할 수 있다.
    
- 악성 스크립트가 실행될 수 있다.
    
- 설정 파일이 변조될 수 있다.
    
- 웹 서버 취약점과 결합해 서버 침해로 이어질 수 있다.
    

따라서 권한 문제를 해결하기 위해 무조건 `chmod 777`을 사용하는 것은 피해야 한다.

## 8. 파일 소유자와 그룹 변경

파일 권한은 소유자와 그룹을 기준으로 적용된다.  
파일의 소유자나 그룹을 변경할 때는 `chown`, `chgrp` 명령어를 사용할 수 있다.

### 소유자 변경

```bash
sudo chown user1 file.txt
```

### 소유자와 그룹을 함께 변경

```bash
sudo chown user1:developers file.txt
```

### 그룹 변경

```bash
sudo chgrp developers file.txt
```

권한을 설계할 때는 단순히 `chmod`만 사용하는 것이 아니라, 소유자와 그룹 설정도 함께 고려해야 한다.

## 9. sudo 명령어

`sudo`는 일반 사용자가 다른 사용자의 권한, 보통 root 권한으로 명령어를 실행할 수 있게 해주는 명령어이다.

예를 들어 일반 사용자가 패키지를 설치하려면 다음과 같이 실행할 수 있다.

```bash
sudo apt install nginx
```

이 명령어는 `apt install nginx`를 관리자 권한으로 실행한다.

sudo를 사용하면 root 계정으로 직접 로그인하지 않고도 필요한 작업만 관리자 권한으로 수행할 수 있다.

---

## 10. sudo 권한 설정

sudo로 실행할 수 있는 명령어는 별도의 설정 파일에서 관리한다.

보통 다음 파일이나 디렉터리에서 관리한다.

```bash
/etc/sudoers
/etc/sudoers.d/
```

sudoers 파일은 문법 오류가 발생하면 sudo 사용 자체에 문제가 생길 수 있다.  
따라서 직접 편집하기보다 `visudo` 명령어를 사용하는 것이 권장된다.

```bash
sudo visudo
```

또는 `/etc/sudoers.d/` 아래에 별도 파일을 만들 수도 있다.

```bash
sudo visudo -f /etc/sudoers.d/user1
```

---

## 11. sudoers 설정 예시

### 특정 사용자에게 모든 sudo 권한 부여

```text
user1 ALL=(ALL) ALL
```

의미는 다음과 같다.

- `user1`: 권한을 부여할 사용자
    
- `ALL`: 모든 호스트에서
    
- `(ALL)`: 모든 사용자 권한으로
    
- `ALL`: 모든 명령어를 실행할 수 있음
    

즉, `user1` 계정은 비밀번호 입력 후 sudo로 모든 명령어를 실행할 수 있다.

---

### 비밀번호 없이 모든 sudo 명령어 실행 허용

```text
user1 ALL=(ALL) NOPASSWD: ALL
```

이 설정은 `user1` 계정이 비밀번호 입력 없이 모든 명령어를 sudo로 실행할 수 있게 한다.

편리하지만 보안상 위험할 수 있다.  
해당 계정이 탈취되면 공격자가 비밀번호 없이 관리자 권한을 사용할 수 있기 때문이다.

따라서 `NOPASSWD`는 반드시 필요한 경우에만 제한적으로 사용해야 한다.

---

### 특정 명령어만 sudo로 실행 허용

```text
user1 ALL=(ALL) NOPASSWD: /usr/bin/systemctl
```

이 설정은 `user1` 계정이 비밀번호 없이 `/usr/bin/systemctl` 명령어를 sudo로 실행할 수 있게 한다.

다만 이 경우에도 주의가 필요하다.  
`systemctl`은 서비스 실행, 중지, 재시작 등을 할 수 있기 때문에 간접적으로 높은 권한을 얻는 데 악용될 수 있다.

따라서 특정 명령어만 허용하더라도 해당 명령어가 어떤 작업을 수행할 수 있는지 반드시 확인해야 한다.

---

## 12. 보안 관점에서 권장되는 운영 방식

OS 계정과 권한을 관리할 때는 다음 원칙을 지키는 것이 좋다.

1. root 계정 직접 사용을 최소화한다.
    
2. 일반 사용자 계정을 사용하고, 필요한 경우에만 sudo를 사용한다.
    
3. 사용자에게 필요한 최소 권한만 부여한다.
    
4. `chmod 777` 사용을 피한다.
    
5. sudo 권한은 사용자별, 명령어별로 제한한다.
    
6. sudoers 파일은 반드시 `visudo`로 수정한다.
    
7. 사용하지 않는 계정은 비활성화하거나 삭제한다.
    
8. 중요한 파일은 소유자와 그룹을 명확히 설정한다.
    
9. 비밀번호 없는 sudo 권한은 신중하게 부여한다.
    
10. 권한 변경 이력을 관리하고 주기적으로 점검한다.
    

---

## 정리

OS 계정과 권한 관리는 서버 보안의 기본이다.

root 계정은 모든 권한을 가지므로 직접 사용을 최소화해야 하며, 일반 사용자에게는 필요한 권한만 부여해야 한다.

파일 권한은 소유자, 그룹, 다른 사용자 단위로 나뉘며 `r`, `w`, `x` 권한을 통해 접근 범위를 제어한다.

`chmod`, `chown`, `sudo`, `sudoers` 설정은 서버 운영에서 자주 사용되지만, 잘못 설정하면 보안 사고로 이어질 수 있다.

따라서 권한 문제를 해결할 때는 편의성보다 보안을 우선하고, 항상 최소 권한 원칙을 기준으로 설정해야 한다.
