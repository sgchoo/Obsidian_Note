# Kafka
- 높은 처리량. 초당 백 만개 이상의 메세지를 처리할 수 있다.
- 수평 확장이 용이하다. 서버, 파티션, 소비자를 늘리면 된다.
- 카프카는 메세지를 파일에 보관해서 메세지가 유실되지 않는다.
- 1개의 토픽이 여러 파티션을 가질 수 있는데, 파티션 단위로 순서를 보장한다. 하지만 토픽 수준에서는 순서를 보장할 수 없다.
- 소비자는 메세지를 언제든지 재처리할 수 있다.
- pull 모델을 사용한다. 소비자가 카프카 브로커에서 메세지를 읽어가는 형식이다.

# Rabbit MQ
- 클러스터를 통해 처리량을 높일 수 있다. 단, 카프카보다 더 많은 자원을 필요로 한다.
- 메모리에만 메세지를 보관하는 큐 설정을 사용하면 장애 상황 시 메세지가 유실될 수 있다.
- 메세지는 큐에 등록된 순서대로 소비자에 전송된다.
- 메세지가 소비자에 전달됐는지 확인하는 기능을 제공한다.
- push 모델을 사용한다. Rabbit MQ 브로커가 소비자에 메세지를 전송한다.

# Redis pub/sub
- 메모리를 사용하므로 지연 시간이 짧고, Rabbit MQ대비 처리량이 높다.
- 구독자가 없으면 메세지가 유실된다.
- 기본적으로 영구 메세지를 지원하지 않는다.
- 모델이 단순해서 사용하기 쉽다.
